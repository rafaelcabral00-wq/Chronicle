# DR-0008: Action Resolution and Randomness Boundary

## Decision Record

Status: accepted.

Accepted option: Option A.

Effective date: 2026-08-07.

Decision:

This document records a new explicit Chronicle project decision. It is not a historical approval from the prototype review process. The prototype `generic-dice` capability remains blocked with `readiness: blocked` and `blockingReasonKey: werewolf-prototype.capability.dice.algorithm-not-frozen`. No pre-existing approved artifact authorizes the executable behavior defined below.

Chronicle hereby approves the following action-resolution and randomness boundary for PLAYABLE-001:

- Chronicle owns all random number generation and dice execution.
- Rule Sets never generate random values directly or indirectly.
- Rule Sets describe what should be rolled by producing a deterministic dice plan.
- Rule Sets interpret raw committed dice results into mechanical outcomes according to approved authority.
- Narrative Intelligence may request or intend an action but cannot choose final mechanical outcomes.
- Application orchestration owns the execution sequence: request → define → execute → interpret.
- Raw dice results and interpreted mechanical outcomes are separately representable.
- A deterministic test RNG must exist so CI never depends on nondeterminism.
- PLAYABLE-001 implements only the approved subset of Werewolf 3E dice mechanics; unresolved mechanics are explicitly deferred.

## Ownership Boundary

- **Chronicle owns**: random number generation, dice execution, evidence commitment, deterministic RNG for tests, orchestration sequence.
- **Rule Set owns**: dice plan definition, Attribute+Ability pool calculation, difficulty input, raw dice result interpretation according to approved authority, canonical findings.
- **Rule Set must not**: call `Random`, `System.Security.Cryptography.RandomNumberGenerator`, `IDiceValueGenerator`, or any other RNG API; generate, script, or influence die faces; persist rolls; call Narrative Intelligence.
- **Narrative Intelligence must not**: own rules, randomness, canonical state, persistence, or mechanical outcome selection.

## Approved Subset for PLAYABLE-001

### Approved for Implementation

- Chronicle-owned generic d10 pool execution contract (quantity, faces, no Werewolf semantics).
- Chronicle-owned deterministic/fixed RNG provider for tests.
- Werewolf runtime operation `character-runtime.define-action-test` (or equivalent) that:
  - validates completed character state;
  - validates Attribute identifier;
  - validates Ability identifier;
  - validates current ratings;
  - enforces applicable character restrictions;
  - calculates dice pool deterministically (Attribute + Ability + modifiers);
  - returns a generic `DiceRollRequest` suitable for Chronicle execution.
- Werewolf runtime operation `character-runtime.interpret-action-roll` (or equivalent) that:
  - receives raw `DiceRollResult` generated by Chronicle;
  - interprets raw dice results into a deterministic mechanical outcome;
  - returns success count, failure/success classification, canonical findings, and stable serialized form;
  - does not roll dice, mutate character state, narrate prose, persist anything, or call Narrative Intelligence.
- Application-level orchestration proving: completed character → define test → execute dice → interpret result → resolved mechanical outcome.
- Deterministic test fixtures and cross-boundary integration tests.

### Explicitly Deferred (Not Approved for PLAYABLE-001)

The following Werewolf 3E mechanics are **not extracted, not frozen, and not approved** for PLAYABLE-001. They must not be implemented, inferred from general system knowledge, or assumed from classic World of Darkness precedent:

- Success threshold (e.g., 8+). The exact threshold is unresolved per EXTRACTION-0004 ambiguity A-001.
- Botch definition and triggering conditions. Explicitly unresolved per EXTRACTION-0004 ambiguity A-001.
- Cancellation behavior: whether 1s cancel successes, and whether cancellation occurs before or after specialization Dice. Explicitly unresolved per EXTRACTION-0004 ambiguity A-001.
- Specialization resolution: additional die generation, chaining, result-of-1 handling on added Dice. Explicitly unresolved per EXTRACTION-0004 ambiguity A-002.
- Result-of-10 behavior without specialization. Explicitly unresolved per EXTRACTION-0004 ambiguity A-001.
- Difficulty range and source (Storyteller-set vs. fixed). Partially documented as contextual but not frozen.
- Minimum Dice pool behavior when pool is zero or modifiers reduce below one.
- Automatic success or failure rules.
- Modifier application rules beyond Attribute+Ability base pool.

These deferred items remain blocked under `werewolf-prototype.capability.dice.algorithm-not-frozen` and must be resolved through a dedicated extraction and semantic review work package before implementation.

## Chronicle Dice Contracts

### DiceRollRequest (Chronicle.Contracts or Chronicle.Application)

```csharp
public sealed record DiceRollRequest(
    string RequestId,
    int DiceQuantity,
    int DiceFaces,
    IReadOnlyDictionary<string, string>? Metadata);
```

### DiceRollResult (Chronicle.Contracts or Chronicle.Application)

```csharp
public sealed record DiceRollResult(
    string RequestId,
    bool Succeeded,
    IReadOnlyList<int> DiceValues,
    IReadOnlyDictionary<string, string> Metadata);
```

Properties:
- `DiceValues` are individually bounded by `[1, DiceFaces]`.
- Ordering is deterministic and matches request order.
- No Werewolf-specific fields.

### IDiceValueGenerator (Chronicle.Infrastructure)

```csharp
public interface IDiceValueGenerator
{
    IReadOnlyList<int> Generate(int quantity, int faces);
}
```

Implementations:
- `SystemDiceValueGenerator`: uses OS cryptographic randomness.
- `ScriptedDiceValueGenerator`: returns fixed sequence for deterministic tests.

## Application Orchestration Flow

```
1. Chronicle.Application receives action resolution request.
2. Resolve completed character via RuleSetRuntimeRegistry.
3. Invoke Werewolf define-action-test with Attribute+Ability+difficulty.
4. Receive DiceRollRequest from Rule Set.
5. Invoke Chronicle dice execution with DiceRollRequest.
6. Receive DiceRollResult (raw d10 faces) from Chronicle.
7. Invoke Werewolf interpret-action-roll with raw DiceRollResult.
8. Receive deterministic mechanical outcome from Rule Set.
9. Return resolved outcome to caller.
```

Chronicle.Application depends only on abstractions (`IRuleSetRuntimeRegistry`, `IDiceValueGenerator`, `DiceRollRequest`, `DiceRollResult`). It does not depend on Werewolf concrete types.

## Scope (PLAYABLE-001)

Approved for implementation:

- Generic d10 dice execution contracts in Chronicle.Contracts.
- `IDiceValueGenerator` abstraction with `SystemDiceValueGenerator` and `ScriptedDiceValueGenerator` in Chronicle.Infrastructure.
- Dice execution use case in Chronicle.Application.
- Werewolf runtime operation for action-test definition (`character-runtime.define-action-test`).
- Werewolf runtime operation for action-roll interpretation (`character-runtime.interpret-action-roll`) with deferred semantics.
- Application orchestration proving the full cross-boundary flow.
- Comprehensive tests for all layers.
- Package metadata and capability updates for `generic-dice`.
- Documentation and evidence artifacts.

## Exclusions

- Werewolf success-counting algorithm (threshold, botch, cancellation, specialization, 10-again).
- Persistence of dice results or interpreted outcomes.
- Combat, damage, or opposed rolls.
- Extended or resisted tests.
- Dramatic systems or task categories.
- Narrative Intelligence integration.
- OpenAI/Ollama/network/database dependencies.
