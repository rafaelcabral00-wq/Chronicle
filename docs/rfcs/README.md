# Requests for Comments

RFCs define Chronicle's product, domain, application, architecture, and contract intent.

## Reading Order

2. [RFC-0002: Product Vision](RFC-0002-Product-Vision.md)

7. [RFC-0027: Rule Set Package Architecture](RFC-0027-Rule-Set-Package-Architecture.md)
8. Build, testing, security, UI, and roadmap RFCs.

## Authority Rules

- RFCs define intent and contracts.
- ADRs choose concrete implementation approaches where needed.
- SPEC documents provide detailed normative contracts for specific areas.

## Status and Supersession

Check front matter before relying on an RFC.

If two RFCs appear to disagree, prefer the later accepted reconciliation or decision request record and then amend the affected documents through the documented process.
